# 로그인 복귀·알림 이동 주소 검증

## 문제와 범위

로그인 화면의 `next` 쿼리는 URL 작성자가 지정할 수 있다. 기존 `startsWith("/")` 검사는 `//redirect.invalid`와 `/\redirect.invalid`도 통과시켜 로그인 완료 후 외부 주소가 `router.push`에 전달됐다. 일반 로그인과 2단계 인증 모두 같은 완료 함수를 사용해 영향을 받았다.

알림 `href`도 같은 접두사 검사에 의존했다. 이 경로는 API 응답에 대한 방어 강화이며, 이번 작업에서 공격자가 해당 알림 값을 생성할 수 있다는 점까지 입증한 것은 아니다. 기존 검사는 trim한 값으로 판정한 뒤 원문으로 이동하는 불일치도 있었다.

Next.js는 신뢰할 수 없는 주소를 검증 없이 라우터에 전달하지 않도록 권고한다. [useRouter 공식 문서](https://nextjs.org/docs/app/api-reference/functions/use-router). 신뢰받는 사이트의 복귀 URL을 외부로 돌리는 위험은 [OWASP 리디렉션 검증 지침](https://cheatsheetseries.owasp.org/cheatsheets/Unvalidated_Redirects_and_Forwards_Cheat_Sheet.html)도 설명한다.

## 변경 정책

- `isInternalHref`가 루트 상대 주소만 허용한다. 절대 URL, `//` 시작, 역슬래시, 앞뒤 공백, ASCII 제어문자는 거부한다.
- 표준 URL 파서로 origin과 점 세그먼트 정규화 결과를 확인한다. 정규화된 경로가 `//`로 시작해 다시 외부 주소로 해석될 수 있는 경우도 거부한다.
- 검증 후 원문을 그대로 사용한다. 쿼리·해시의 정상적인 인코딩, 한글 검색어, 쿼리 안의 외부 주소 문자열은 유지한다. 임의로 반복 디코딩하지 않는다.
- 위험하거나 없는 로그인 복귀 주소는 `/feed`로 폴백한다. 2FA도 동일하며 임시 비밀번호 변경 화면의 우선순위는 유지한다.
- 위험한 알림 주소는 읽음 상태와 관계없이 링크를 렌더링하지 않고, 클릭 핸들러에서도 이동을 막는다. 읽음·삭제 버튼은 유지한다. 알림의 기존 `/` 비활성 정책도 유지한다.
- 인증 API, 쿠키, 세션, 권한, 백엔드 저장 데이터는 변경하지 않는다.

## 검증 결과

- 수정 전 회귀 테스트 40개 중 20개 실패로 허점을 재현했다.
- 수정 후 신규 테스트 71개 통과: URL 정책, 로그인·2FA 복귀, 임시 비밀번호 우선순위, 로그인 실패, 알림 링크와 읽음·삭제 버튼.
- 웹 전체 테스트 444개(60개 파일), TypeScript, ESLint, Next.js 프로덕션 빌드 통과.
- 격리된 Chrome + 프로덕션 웹 + 로컬 모의 API로 확인:
  - `next=%2F%2Fredirect.invalid` 로그인 → `/feed`.
  - `next=%2F%5Credirect.invalid` 2FA 완료 → `/feed`, 해당 외부 호스트 요청 없음.
  - 정상 로그인 → `/notifications?from=login#list`, 쿼리·해시 보존.
  - 위험한 읽음/미읽음 알림 모두 링크 없음, 정상 알림만 링크 표시.
  - 정상 알림 클릭 → 읽음 API 200 → `/about?from=notification#intro`, 전체 문서 재요청 없이 이동.
  - 확인한 흐름에서 콘솔 오류·경고 없음.

실제 DB·백엔드를 연결한 전체 E2E 및 원격 CI는 이번 로컬 검증 범위에 포함하지 않았다. 모의 API는 운영 계정·쿠키를 사용하지 않았으며 검증 종료 후 서버와 격리 탭을 종료했다.
